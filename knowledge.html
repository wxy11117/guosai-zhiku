    怎么快速选模型？

    要预测未来先看 预测类：回归、灰色预测、ARIMA、指数平滑、LSTM。
    要找最优方案先看 优化类：规划模型、动态规划、启发式算法、多目标优化。
    要综合排序 / 选优先看 评价决策类：AHP、熵权、TOPSIS、VIKOR、DEA、模糊综合评价。
    要判断类别 / 风险先看 分类识别类：逻辑回归、决策树、随机森林、SVM、Boosting。
    要做路径 / 运输 / 调度先看 图论 + 优化：最短路、TSP、VRP、网络流、整数规划。
    要模拟复杂系统先看 仿真类：蒙特卡罗、离散事件仿真、系统动力学、多智能体。

    国赛中最常见的“组合打法”

    数据清洗 → 统计分析 → 主模型 → 误差/敏感性分析

    这是最常见的总结构，几乎所有数据题都适用。

    PCA / 因子分析 + 回归 / 分类

    变量很多时先降维，再做预测或判别，适合高维数据题。

    熵权 / AHP + TOPSIS / VIKOR

    权重确定 + 排序选优，是评价决策题的经典双层框架。

    机理方程 + 数值求解 + 参数优化

    物理、生物、环境类题目很常见，先建立机理，再用优化校准参数。

    聚类 + 分类 / 画像

    先分群，再解释每群特征，适合用户分层、区域分类与行为识别。

    最短路 / VRP + 启发式算法

    运输路径与调度问题中，常用图论建模后再用遗传/蚁群等求近优。

    预测类 / 时间序列类

    适用：趋势预测、销量 / 产量 / 温度 / 浓度 / 价格等连续变量预测
    线性回归 / 多元回归 / 多项式回归

    适合解释变量和目标变量关系较清晰的场景；优点是可解释性强，论文表达最友好。

    灰色预测（GM(1,1)、Verhulst、灰色关联）

    适合样本少、信息不完全的题；是国赛里非常常见的“短平快”模型。

    ARIMA / SARIMA / 指数平滑 / Holt-Winters

    适合纯时间序列、有趋势或季节性的预测题。

    随机森林回归 / XGBoost / LightGBM / 神经网络

    01线性回归 / 多元回归预测与时间序列 · 9 篇明确关联展开学习 ＋
    通俗理解

    把多个影响因素和一个结果之间的关系，用一条“最能代表整体趋势”的直线或平面表达出来。

    核心思想 / 数学直觉

    假设目标变量可以由若干自变量的线性组合近似解释，通过最小化残差平方和估计系数。

    ŷ = β₀ + β₁x₁ + … + βₚxₚ
    什么时候用

    需要解释“哪些因素影响结果、影响方向和幅度”，或需要一个强可解释性的预测基线时。

    举例

    已知温度、湿度、客流量，预测某商场当天销售额；同时看每个变量的系数判断影响方向。

    国赛怎么用

    先做相关性与共线性检查，再建模；报告 R²、残差、显著性，并对关键系数做业务解释。

    常见坑

    不要看到相关就写因果；非线性明显、异方差严重或变量高度共线时，直接线性回归会失真。

    CUMCM FIELD NOTES · 国赛实战经验

    国赛不是“模型越高级越好”，而是把问题解决得又准、又稳、又清楚

    这部分结合全国组委会评阅标准、2026 年最新论文与 AI 使用规范，以及公开的国一 / 国奖队伍经验整理。核心目标只有一个：让你在三天里把有限的时间花在真正影响评奖的地方。

    摘要模型选择结果核验排版团队分工比赛节奏AI 使用
    PRACTICAL
    PLAYBOOK
    先记住国赛的官方评阅逻辑：评奖主要看假设是否合理、建模是否有创造性、结果是否正确、文字表达是否清晰。换句话说，模型只是解决问题的工具；一个复杂但错位的模型，通常不如一个简单、贴题、验证充分的模型。
    01 · ABSTRACT

    摘要一定要认真写：它不是“前言”，而是整篇论文的压缩版

    摘要要形成完整逻辑链：解决什么问题 → 做了什么关键处理 → 建了什么模型 → 怎么求解 / 验证 → 得到了什么具体结果。不要只写“建立某模型，结果良好”，而要给出最有辨识度的模型特点和关键数值结论。摘要最好在主体完成后再统一重写，保证与正文完全一致。

    可以让 AI 帮你检查语言、压缩表达、寻找逻辑断点，但不要把未经核验的 AI 文字直接贴进去，更不能让 AI 凭空补“模型效果显著”“结果合理”等主观结论。
    02 · MODEL FIT

    模型在“准”，不在“炫”：贴题比高级更重要

    不要为了写上神经网络、遗传算法、深度学习就强行上复杂模型。先问四件事：这个模型是否对应题目的真实机制？数据量够不够？参数能否解释？结果能否验证？ 如果基础模型已经能稳定解决问题，就先把它做扎实；真正需要时，再用复杂模型做改进或对照。

    高分论文的高级感通常来自“问题拆得准、假设有依据、模型链条闭环”，而不是模型名字听起来有多复杂。
    03 · RESULTS

    国赛尤其重视结果正确性：数值、约束、单位都要经得住查

    全国组委会把“结果的正确性”直接写进评奖标准。最后答案不是程序跑出来就结束：要检查数量级、单位、边界条件、约束是否满足，最好再用另一种算法、极端情形或已知样本做交叉验证。模型结果必须能回到原题逐问作答，不能只展示指标却没给题目要的最终方案。

    与美赛常见的强叙事、强 Summary Sheet 呈现相比，国赛实战中更不要“为了好看而堆图”。图表要有，但每张图都应服务于结论、检验或解释。
    04 · LAYOUT

    排版不是最后半小时做的美容，而是论文可读性的一部分

    提前准备统一模板：标题层级、公式编号、图表标题、字体字号、段前段后、参考文献格式都提前固定。正文保持结构一致，图表清晰且编号连续，关键结果用表格或粗体适度突出。不要满页彩色、花哨渐变或大段截图；整洁、稳定、像一篇科技论文比“设计感”更重要。

    2026 官方格式规范要求摘要原则上不超过一页、正文不设目录且不超过 30 页；程序和支撑材料也必须与论文结果一致。
    05 · PROBLEM FIRST

    先学会“看题”，再学算法：不要拿着模型去套题

    公开国奖经验反复强调：备赛不应只按算法目录学习，而应建立“题型 → 问题结构 → 可用模型 → 验证方式”的映射。拿到题后，三个人先统一问题理解，拆清输入、输出、约束和每一问之间的依赖，再决定模型路线。

    这也是为什么本资料库把“赛题原文 → 模型路线 → 优秀论文”放在一起：先理解题，模型才有意义。
    06 · VALIDATION

    别只给结果，要告诉评委“为什么可以相信这个结果”

    至少准备一类验证：拟合误差、交叉验证、残差分析、灵敏度分析、稳健性测试、极端情景检验或与基准模型比较。对于优化题，还要验证约束可行性；对于预测题，不要只报训练集指标；对于评价题，要检查权重变化是否会导致排序剧烈反转。

    模型检验不是可有可无的尾巴，它实际上是在替你的结论做“可信度证明”。
    07 · TEAMWORK

    分工要明确，但绝对不能割裂：三个人必须共享同一套逻辑

    “建模手 / 编程手 / 论文手”只是主责，不是三条互不相干的流水线。论文手必须听懂模型，编程手要理解约束和数据，建模手也要参与核心模型部分的写作。国一队伍经验特别强调反复沟通，确保三个人对问题的理解一致。

    最危险的情况是：模型手说一套、代码实现另一套、论文最后又写成第三套。
    08 · WRITING FLOW

    论文不要等模型全做完才开始写：边做边沉淀

    第一天就可以写问题重述、符号表、基础假设和数据分析；模型一旦确定，立刻记录模型动机、公式来源和参数意义。图表生成后马上写结论，不要把所有写作都压到最后一晚。公开国一经验建议论文手前期先做数据侧写、可视化和模板准备，从而减少最后阶段的写作拥堵。

    最后阶段最宝贵的时间应该留给：摘要、结果核验、前后文一致性、排版和提交检查。
    09 · EVIDENCE

    每个重要假设都要有来源或解释，尽量少做“拍脑袋假设”

    赛题允许合理补充假设，但假设必须能解释。可以来自题意、物理规律、公开资料、统计特征或为了模型可解而做的合理简化；随后说明该假设可能造成什么影响。公开数据、公式和他人成果要规范引用，别把网络上看到的数字直接写进正文却不给来源。

    “为了方便计算，假设……”不是充分理由。至少要解释为什么这个简化不会破坏问题的主要机制。
    10 · STOP RULE

    遇到卡点要有止损机制：完成一套闭环答案，比半套“神模型”更重要

    如果某个复杂模型长时间调不通，不要全队陪它耗死。先保证每一问都有可交付结果，再逐步替换和升级。国一经验明确建议：对于集体讨论后仍难以解决的问题，不要停留过久，应先保证比赛进度。

    比赛不是论文开题。你只有三天，必须始终维护一个“现在就能交”的版本。
    关于 AI：2026 国赛规则已经正式明确。 参赛队可以使用大语言模型、生成式 AI、代码辅助工具和 AI 智能体，但核心建模与分析必须由参赛队主导，并对 AI 参与内容进行人工审查与核实；使用 AI 时还需要在论文中设置“AI 工具使用声明”，并在支撑材料里说明具体用途和核验情况。因此，AI 很适合做语言润色、代码调试、格式检查和头脑风暴，但不要把未经核验的 AI 输出直接当成结论、数据或核心建模成果。
    开赛前 2–4 小时快速读全题、比较题型、检查数据和附件；三人共同决定选题，不要只凭“模型会不会”选题。
    第一阶段 · 闭环优先拆问题、做数据清洗、建立能跑通的基础模型。先保证每一问都有解，再升级模型。
